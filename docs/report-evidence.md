## 기능 변경 1 홈 소개 직접 배치

- 관련 기준은 P59·P47·P80이며 화면 검증은 P31·P32와 연결한다.
- 사용자가 확인한 사실은 소개가 다른 상세 페이지에 있었다는 것이다. 홈에서 사라진 오류라고 단정했던 이전 설명은 사용자가 11월 8일 정정했다. 보고서는 사용자가 발견하지 못했던 상세 내용을 원하는 홈 위치로 옮긴 개선으로 기술한다.
- 변경 전에는 홈 설정의 homeInfoParams에 Title만 있었고, 소개 문장은 posts/hello.md의 description에 있었다. 이름·소개를 함께 보려면 별도 상세 화면으로 이동해야 했다.

```json
"homeInfoParams": {
  "Title": "정다희"
}
```

- 변경 후에는 홈 설정에 소개 Content를 넣고 홈 partial을 상세 화면의 제목·설명 클래스 구조로 바꿨다. 소개 글은 hiddenInHomeList로 중복 카드를 숨겼다.

```json
  "Title": "정다희",
  "Content": "컴퓨터인공지능학부 25학번 정다희입니다."
}
```

```html
<h1 class="post-title">{{ .Title | markdownify }}</h1>
<div class="post-description">{{ .Content | markdownify }}</div>
```

- 수정 위치는 `site/pages.json`, `site/layouts/_partials/home_info.html`, `site/content/posts/hello.md`다. 핵심 커밋은 https://github.com/jeongdahui731/MyProfile/commit/019a811633c1e1a3f8ec7b878e56fc42697ff847 이다.

## AI 사례 1 홈 소개 배치 개선

- 도구는 Codex이며 채팅 UI에 표시된 정확한 모델명은 보존하지 않아 미표시로 적는다. 수행일은 2026년 11월 7일이며 19시 36분 작업 기록이 있다.
- 목적은 상세에 있던 이름·소개를 홈으로 옮기고 중복 구성을 정리하는 것이다.
- 실제 요청 핵심 원문은 다음과 같다.

> 그 흰색 칸 눌러서 들어가면 자기소개랑 이름이 있는데 그걸 그대로 홈 화면으로 옮기고 싶어 홈화면에 있는 이름은 지우고 그 흰색 칸 안에 있는 글씨들을 그 위치 그대로 옮기고 싶어 이해했어?

> 수정해줘

- AI 핵심 응답 요약은 homeInfoParams.Content를 추가하고 home_info partial에 상세 화면의 제목·설명 클래스를 사용하며 기존 소개 카드는 숨기겠다는 제안이다. 이 문장은 원문 인용이 아닌 요약이다.
- 본인 판단은 사용자가 상세를 클릭해야 보이는 구성을 원하는 첫 화면으로 옮기기로 선택하고 실제 수정을 요청한 것이다. 이후 제목은 34px로 줄이도록 추가 조정했다.
- 반영 경로와 커밋은 기능 변경 1을 참조한다. AI는 실제 파일 수정과 정적 검사·후속 브라우저 검증을 수행했고, 사용자는 문구·위치·디자인을 선택하고 커밋·push를 수행했다.
- 예상 결과는 홈에서 이름과 소개가 바로 보이고 중복 소개 카드가 없는 것이다. AI 실제 공개 확인 결과는 예상과 일치했고 그림 1·3이 근거다. 사용자의 당시 직접 검사 동작 상세는 미제공이다.
- 한계는 최초 AI 설명이 홈과 상세의 표시 차이를 소개가 사라졌다는 표현으로 다뤘다는 점이다. 사용자가 소개는 다른 페이지에 있었다고 정정했으므로 최종 보고서에서는 배치 개선으로 기록한다.

- 목적은 실제로 만든 HTML·이미지를 공개 사이트에서 열고 원본 코드를 확인할 근거를 연결하는 것이다.
- 실제 요청 핵심 원문은 다음과 같다.

> 일단 이게 만든 홈페이지인데 이거 먼저 넣을게

## AI 활용 범위와 원문 확보

전체 AI 활용에는 이 수행 채팅의 기준 분석·계획, 설정·코드·문구 반영, 사용자 요구 확인, 정적 검사, 배포 오류 분석, 공개 브라우저 검증, README·검증표·커밋 집계·보고서 근거 정리가 포함된다. 별도 질문용 채팅에서 받은 도움은 사용자가 아직 내용을 제공하지 않아 구체적으로 기록하지 못했다.

대표 사례는 위의 실제 작업에서 선택했다. 처음 후보였던 배포 경로 오류 수정과 키보드 초점 개선은 대표 사례로 수행한 별도 개선이 아니므로 최종 사례로 사용하지 않는다. 현재 키보드 기본 초점이 보이는 관찰과 초점 개선 코드를 새로 작성했다는 주장은 구분한다.

보고서에는 위 요청 핵심 원문을 텍스트로 옮겨도 된다. 읽을 수 있는 캡처를 쓰려면 해당 요청·AI 응답·사용자 판단이 나타나는 부분만 촬영한다. 시작 메시지나 전체 대화를 제출할 필요는 없다. 비밀값·계정 정보·불필요한 개인정보는 가린다.

## 출처와 남은 확인

- 테마는 MIT이며 루트 LICENSE와 site/themes/template/LICENSE의 고지를 사용한다. 상세 출처 목록은 README의 출처와 제작 구분 절에 있다.
- 사용자는 토트넘 로고를 네이버 이미지에서 찾았다고 답했다. 검색 서비스는 원본 권리자의 페이지와 같지 않으므로 원본 URL·제작자·이용 조건은 아직 미확인으로 적는다.
- 실제 프로필 카드 HTML은 사용자 제공 자료이며 웹 구현·활동 내용도 사용자가 제공한 문안을 반영했다. AI 도움을 받은 사이트 템플릿·CSS·자료 연결과 구분한다.
- 브라우저 엔진 버전·OS 제품명, 200%가 표시된 캡처와 사용자 검사 시각, 새 환경 빌드 재현 등은 검증표의 미확인 사항을 따른다.
- 최종 보고서는 교수님 양식의 필수 목차·표를 채우고 DOCX·PDF로 만든 뒤 모든 페이지와 검색·복사·실제 주소 링크를 검사해야 한다. 이 파일은 보고서 작성용 근거이며 제출 PDF 자체가 아니다.
